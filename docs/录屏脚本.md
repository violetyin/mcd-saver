# 录屏脚本（2 分 30 秒版）

> 用途：WaytoAGI 用餐赛道要求「能用的作品 + 使用说明或录屏」。以当前网页实际返回为准，录制前不要预设固定价格或券数。

## 录制前 3 分钟检查

1. 启动服务：`cd /d/1024-mcd-saver && node web/server.mjs`，浏览器开 `http://127.0.0.1:4173`
2. 浏览器全屏（F11），缩放调到 100%，关掉其它标签页
3. **不要打开 `.env`、不要打开终端里的 `mcp.json`**——Token 会露在画面里
4. 录屏工具：Windows 自带 `Win + G`（Xbox Game Bar）就够，或 OBS
5. 先空跑一次，确认门店、账户信息和算价都能返回，再正式录

## 一句话记住的核心卖点（评委问答时用）

- **真调用**：一次运行 20 次以上 MCP 调用，页面底部有计数。
- **不是估算**：金额全部来自 `calculate-price`，含券；标价相加在这个场景永远是错的。
- **省多少有口径**：把套餐里的单品分别再买一次，用**同商品同份数**的单点价来比；不拿不同餐品硬比。
- **数据不足就说不足**：营养表缺麦炫酷这类饮品，就把「几项中几项可查、缺哪项」写出来，不拿部分数据冒充全量。

## 可能被追问的三个问题

**Q：为什么先选门店？**
A：优惠券按门店生效（`query-store-coupons` 必须带 `storeCode`）。不先定门店，查到的券就是错的，算出来的价也就是错的。

**Q：省 41% 是怎么算的？**
A：把那套套餐里默认包含的两件单品，各自按单点再算一次价（同商品、同份数），47 元是分开买的价格，27.8 是套餐价，差额 19.2 元。不是拿别的套餐硬比。

**Q：会不会自动下单？**
A：不会。只有用户在网页上确认后才会调用 `create-order` 创建待支付订单；可逐笔取消，默认不付款。
