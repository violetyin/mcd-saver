# 录屏脚本（2 分 30 秒版）

> 用途：WaytoAGI 用餐赛道要求「能用的作品 + 使用说明或录屏」。这份是照着念就能录的版本。

## 录制前 3 分钟检查

1. 启动服务：`cd /d/1024-mcd-saver && node web/server.mjs`，浏览器开 `http://127.0.0.1:4173`
2. 浏览器全屏（F11），缩放调到 100%，关掉其它标签页
3. **不要打开 `.env`、不要打开终端里的 `mcp.json`**——Token 会露在画面里
4. 录屏工具：Windows 自带 `Win + G`（Xbox Game Bar）就够，或 OBS
5. 先空跑一次（点一次"算一算"），确认这次出的是好数据，再正式录

## 演示参数（就用这组，数字最好看）

| 项 | 值 |
|---|---|
| 人数 | 2 |
| 预算 | 100 元 |
| 忌口 | 不选 |
| 城市 / 商圈 | 武汉 / 光谷 |
| 看热量 | 勾上 |

预期结果：门店「武汉光谷通信广场餐厅」，方案 1 实付 ¥27.80、人均 ¥13.90、比单点省 ¥25.20（48%），有 1 张「麦辣鸡腿堡三件套」券。

## 一句话记住的核心卖点（评委问答时用）

- **真调用**：一次运行 20 次以上 MCP 调用，页面底部有计数。
- **不是估算**：金额全部来自 `calculate-price`，含券；标价相加在这个场景永远是错的。
- **省多少是比出来的**：跟「一样样单点」的同口径基线相减，不是自己编的折扣。

## 可能被追问的两个问题

**Q：为什么先选门店？**
A：优惠券按门店生效（`query-store-coupons` 必须带 `storeCode`）。不先定门店，查到的券就是错的，算出来的价也就是错的。

**Q：为什么不下单？**
A：`create-order` 会产生真实订单和支付。第一版刻意停在"给建议"，把决定权留给用户。要接下单，参数已经齐全，随时能加。
