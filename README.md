# 麦门省钱助手（mcd-saver）

用一句话说清一件事：**「我们 N 个人，预算 X，不吃辣，麦当劳点什么最划算」——它真的去查门店、菜单和你手里的券，然后逐个组合算出实付价。**

不是把标价加起来估个总数，每一分钱都来自麦当劳 MCP 的 `calculate-price`。

> 本项目为「1024 超能 Coding 周末」用餐赛道 + 麦当劳程序员创意开发大赛参赛作品，由作者独立开发，非麦当劳官方产品。餐品、价格、优惠以麦当劳官方渠道实时结果为准。

---

## 它解决什么问题

在麦当劳点餐时，最划算的选择几乎从来不是「一个人一个汉堡」：

- 一份 `随心配 1+1` 13.9 元，能拿到主食+饮品；
- 账户里躺着一张「麦辣鸡腿堡三件套」券，46 元的套餐券后 22.9 元；
- 两个人一起点一份多人餐，比各点各的便宜近一半。

但这些都要你自己去翻菜单、翻券、心算，还经常算错，因为**券只在特定门店、特定场景生效**，标价相加和实付价完全是两回事。

这个 Skill 把这件事变成一条命令。

## 真实效果（北京建外 SOHO 店，2026-10-24 实测）

```
📍 麦当劳北京建外SOHO(A座)餐厅（距离 269m）
🥤 需求：2 人 · 预算 ¥100
🎟  可用券：1 张（麦辣鸡腿堡三件套）
📊 单点基线（牛肉堡单品精选×2 + 灰焰圆筒×2 + 纯悦×2）：¥53.00

方案 1｜精选超值随心配 ×2
   ── 实付 ¥27.80，人均 ¥13.90
   ── 比一样样单点少花 ¥25.20（48%）
   · 套餐默认含：那么大鸡排（椒盐风味） + 怡泉+C麦炫酷 + 阳光柠檬红茶中杯

方案 3｜用券：麦辣鸡腿堡三件套 + 牛肉堡单品精选×1
   · 麦辣鸡腿堡3件套 ×1   ¥22.90（原价 ¥46.00）
   ── 实付 ¥36.90（标价 ¥60.00），券省 ¥23.10（39%）
```

一次跑完真实调用麦当劳 MCP **约 20 次**，覆盖门店、菜单、券、算价、套餐构成、营养。

## 安装

```bash
git clone <本仓库地址>
cd mcd-saver
cp .env.example .env      # 填入你的 MCP Token
```

`.env` 里写：

```
MCD_MCP_TOKEN=你的Token
MCD_CITY=北京
MCD_KEYWORD=国贸
```

Token 在 https://open.mcd.cn/mcp 用手机号登录 → 右上角「控制台」→「激活」→ 复制。

**不需要 `npm install`**：全部零依赖，Node.js ≥ 18 即可。

## 使用

```bash
# 两个人 100 块，带营养信息
node src/cli.mjs --people 2 --budget 100 --nutrition

# 一个人 30 块，不吃辣，指定商圈
node src/cli.mjs -p 1 -b 30 --avoid 辣 --city 北京 --keyword 国贸

# 知道门店编号，直接跳过搜索
node src/cli.mjs -p 3 -b 150 --store 1950564

# 结构化输出，便于接网页 / 机器人
node src/cli.mjs -p 2 -b 100 --json
```

| 参数 | 含义 |
|---|---|
| `-p, --people` | 用餐人数 |
| `-b, --budget` | 预算（元）；加 `--per-person` 变成人均预算 |
| `--avoid` | 忌口：辣 / 牛肉 / 鸡肉 / 猪肉 / 鱼 / 咖啡 / 冰 |
| `--city` `-k, --keyword` | 门店搜索范围与商圈关键词 |
| `--store` | 直接指定 storeCode |
| `--nutrition` | 附带热量 / 蛋白质 / 脂肪 |
| `--json` | 输出 JSON |

## 网页版（路演/录屏用）

```bash
node web/server.mjs        # 打开 http://127.0.0.1:4173
```

点选人数、预算、忌口，直接出三套方案卡片。Token 只在服务端，前端拿不到，也不需要额外依赖。

## 作为 WorkBuddy Skill 使用

把整个仓库目录放进 `~/.workbuddy/skills/mcd-saver/`，之后在 WorkBuddy 里直接说：

> 我们两个人，预算 100，不吃辣，帮我点麦当劳

Skill 会自动带上门店、预算、忌口去跑引擎。详见 [SKILL.md](./SKILL.md)。

也支持走 WorkBuddy 连接器直连：在【连接器】→【自定义连接器】里配

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer YOUR_MCP_TOKEN" }
    }
  }
}
```

## 目标用户

1. **一个人吃午饭的上班族**：预算固定，想吃饱又不想多花钱。
2. **两三个同事/朋友拼单**：人数一多，套餐和多人餐的差价就拉开了。
3. **手里攒了一堆券不知道怎么用的人**：券按门店生效，最容易白躺过期。
4. **想控制热量的人**：`--nutrition` 会把套餐里真实餐品的热量加起来。

## 工作原理

1. `query-nearby-stores` 定门店（到店自取 `beType=1`，不传 `beCode`）。
2. `query-meals` 拿当店菜单，按「多人餐 / 单人套餐 / 主食 / 小食 / 饮品」分桶。
3. `query-store-coupons` 拿本店可用的券——**换门店券就变，所以必须先定门店**。
4. 用模板生成候选组合（券 / 单人套餐 / 多人餐 / 自由搭配 / 完整一套），控制在 18 个以内。
5. 每个候选调 `calculate-price` 算实付，剔除异常返回。
6. 再算一条「一样样单点」的基线，两者相减得到真实省下的钱。
7. 前三个方案补 `query-meal-detail` 说明套餐里有什么，`--nutrition` 时加营养。

细节与踩过的坑见 [MCP_INTEGRATION.md](./MCP_INTEGRATION.md)。

## 边界

- **不下单**：`create-order` 会产生真实订单和支付，本版不碰。
- **不承诺绝对最低价**：枚举的是有限候选，结论是「在试过的组合里最划算」。
- **忌口是启发式**：按餐品名匹配，套餐内部构成仍要看门店当日在售。
